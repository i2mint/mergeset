mergeset.log#

The evaluation log: append-only JSONL, and the single source of truth.

Every expensive evaluation is written here once and never re-run. The log also carries the monotone closure: because good sets are (approximately) downward closed, a passing set marks all of its subsets known-good, and a failing set marks all of its supersets known-bad. That closure is computed lazily from the stored rows rather than materialized, so the file stays small and honest.

Monotonicity is a strong prior, not a law: a change may contain the fix that makes another change work, and flaky tests break it outright. Violations are detected and reported (EvaluationLog.monotonicity_violations()) instead of being silently trusted.

A row is an answer about commits, not about ids. Once the log is pinned (EvaluationLog.pin()) to the base and the head of each change in play, only rows evaluated against those same commits count — rows about an older head of a rewritten branch are kept on disk and in EvaluationLog.rows, and simply not matched (i2mint/mergeset#23). The same holds for what was run: rows judged by another validator (another command, other stages) are kept and not matched (i2mint/mergeset#32).

class mergeset.log.EvaluationLog(store=None, *, pins=None, trust_unpinned=False)[source]#

Bases: object

Append-only record of evaluations, plus the monotone closure over it.

Parameters:

  • store (Any) – Persistence seam. A path (str/PathLike) is wrapped in JsonlLines; pass StoreLines to put the log in an artifact store (S3 and friends), or MemoryLines for an ephemeral log. With no argument at all the log goes to the artifact store’s evaluations/adhoc.jsonl — never the working directory.

  • pins (Optional[Pins]) – The commits the questions are about (see Pins and pin()). Unpinned, every row counts, as before pinning existed; mergeset.analyze() always pins.

  • trust_unpinned (bool) – Let rows that record no commits at all (written before i2mint/mergeset#23, or by an unpinned log), or no validator while the pins name one (written before i2mint/mergeset#32), count as matches once the log is pinned. Off by default, because such a row may be about a head that has since moved, or judged by a command that has since changed — which is the defect pinning exists to close. Turn it on only when you know neither has changed since those rows were written; it is the migration path for an old log. A row whose recorded commits or validator differ never counts.

>>> log = EvaluationLog(MemoryLines())
>>> from mergeset.base import Evaluation, Verdict
>>> _ = log.record(Evaluation(frozenset({'a', 'b'}), Verdict.PASS))
>>> bool(log.known(frozenset({'a'})))          # subset of a passing set
True
>>> log.known(frozenset({'a'})).verdict.value
'pass'
>>> _ = log.record(Evaluation(frozenset({'c', 'd'}), Verdict.FAIL))
>>> log.known(frozenset({'a', 'c', 'd'})).verdict.value   # superset of a failing set
'fail'
>>> log.known(frozenset({'a', 'c'})).verdict is None
True
caching(evaluate, *, infer_pass=True)[source]#

Wrap evaluate so known sets are answered from the log.

The returned callable is what the solver should be handed: it never spends a real evaluation on a set the log can already decide.

infer_pass=False runs a set whose PASS would only be inferred from a passing superset, and records it: for a caller that needs an exact PASS behind every claim (a cheaper tier on the way to a deeper one). Exact rows and inferred FAILs are still answered from the log.

>>> log = EvaluationLog(MemoryLines())
>>> _ = log.record(Evaluation(frozenset('ab'), Verdict.PASS))
>>> runs = []
>>> def run(s):
...     runs.append(set_key(s))
...     return Evaluation(s, Verdict.PASS)
>>> log.caching(run)(frozenset('a')).cached, runs
(True, [])
>>> log.caching(run, infer_pass=False)(frozenset('a')).cached, runs
(False, [('a',)])

pin(*, base, heads, validator=None, resolver=None)[source]#

Scope this log to base, these heads and validator; returns self.

validator is the fingerprint of what the questions will be asked of (mergeset.validation.fingerprint_of()); None matches rows on commits alone. resolver is how their sets are merged (mergeset.oracle.resolver_fingerprint_of()): rows whose outcome a different resolver decided stop counting; None ignores it.

pinned() is the same without changing this object.

From here on, reading (known(), exact(), the closure, iteration, len) sees only rows evaluated against these commits, and record() stamps new rows with them. Nothing is removed: the other rows stay in the store and in rows, and are reported by stale and unpinned.

Return type:

EvaluationLog

>>> from mergeset.base import Evaluation, Verdict
>>> log = EvaluationLog(MemoryLines()).pin(base='B', heads={'a': 'A1'})
>>> _ = log.record(Evaluation(frozenset('a'), Verdict.PASS))
>>> log.known(frozenset('a')).verdict.value
'pass'

>>> log.known(frozenset('a')).verdict is None, len(log.rows), len(log.stale)
(True, 1, 1)

class mergeset.log.Pins(base, heads, validator=None, resolver=None)[source]#

Bases: object

What a question is about: the base, each change’s head sha, the validator.

A row matches when it was merged onto the same base and every change it holds is in play with the same head. A row holding a change that is not in play does not match: its head for that change is unchecked, and such a row would otherwise surface as an “established” set recommending a change nobody asked about, or as a monotonicity violation between two heads of it.

>>> from mergeset.base import Evaluation, Verdict
>>> pins = Pins('B', {'a': 'A1', 'b': 'B1'})
>>> row = Evaluation(frozenset('ab'), Verdict.PASS,
...                  base_sha='B', heads={'a': 'A1', 'b': 'B1'})
>>> pins.matches(row)
True
>>> pins.matches(replace(row, heads={'a': 'A0', 'b': 'B1'}))  # a rewritten
False
>>> pins.matches(replace(row, base_sha='B0'))                 # base moved
False
>>> Pins('B', {'a': 'A1'}).matches(row)          # b is not in play
False

With a validator fingerprint, a row must also have been judged by that validator. A row recording none (written before i2mint/mergeset#32) is not refuted, only incomplete: see EvaluationLog.unpinned.

>>> pins = Pins('B', {'a': 'A1', 'b': 'B1'}, validator='command:1')
>>> pins.matches(replace(row, validator='command:1'))
True
>>> pins.refutes(replace(row, validator='command:2'))   # the command changed
True
>>> pins.matches(row), pins.refutes(row)                # recorded no validator
(False, False)

class mergeset.log.StoreLines(store, key)[source]#

Bases: object

Lines backed by one key of a MutableMapping — the non-file backend.

JsonlLines is the right thing over a filesystem: open(..., 'a') is a true append. An object store has no append, so this reads, concatenates and writes back. That is honest about the cost rather than pretending, and it is what lets the evaluation log — the source of truth — reach S3 through the same seam as everything else.

A missing key reads as empty rather than raising, so a first run works.

>>> backing = {}
>>> lines = StoreLines(backing, 'run.jsonl')
>>> list(lines)
[]
>>> lines.append({'a': 1}); lines.append({'a': 2})
>>> [d['a'] for d in lines]
[1, 2]
>>> backing['run.jsonl']
'{"a": 1}\n{"a": 2}\n'
