mergeset.analysis#

The facade: one call that goes from a repository to a merge plan.

analyze is the “simple thing made simple” entry point. It wires together the pieces — sources, cheap pre-oracles, file-overlap decomposition, the expensive oracle, the log, the search — with defaults that work out of the box, and every piece stays replaceable by one keyword argument.

The order of operations is the whole point, because it is the order of cost:

  1. free: per-change CI status (a red singleton is a conflict of size one);

  2. milliseconds: pairwise git merge-tree textual conflicts;

  3. milliseconds: file-overlap components — independent subproblems;

  4. minutes each: the real merge-and-test oracle, only on what is left.

property evaluations: int#

How many expensive evaluations this analysis rests on.

Counted from the log, which is the source of truth, not from the search state, which only knows what this process ran. Regenerating a report from a complete log spends nothing, and the search-state number then reads 0 — so the better the cache worked, the more the archived report understated the work. A real 18-candidate run that cost 9 evaluations and 344 s reported “0 expensive evaluations spent”.

Rows are counted when they decided something about this candidate set: a recorded PASS or FAIL (an ERROR established nothing) over a subset of the changes in play (so an older run’s rows for a different candidate set in the same log are not claimed as this analysis’s work). The base check counts — it is an evaluation, and on a real project it is one of the slowest.

property evaluations_this_run: int#

How many expensive evaluations this process spent.

The number a progress display wants — 0 on a re-run is correct here and misleading in a report. See evaluations.

property exhausted: bool#

The stacks edges whose child head really contains the parent’s head, so merging the child brings the parent along. Only these let the oracle merge a tip alone; any other parent is merged explicitly, or the row would name a parent head that was never in the tree (#23).

mergeset.analysis.analyze(repo, changes, *, base=None, validate=None, resolver=None, log=None, log_path=None, trust_unpinned=None, artifacts=None, weight=None, pairwise_preoracle=True, decompose=True, component_local=None, use_ci_status=True, check_base=True, max_evaluations=None, max_seconds=None, max_sets=None, worktree_root=None, reuse_worktree=None, on_event=None)[source]#

Find the maximal sets of changes that merge and validate on base.

Parameters:

  • repo (str) – Path to the git repository.

  • changes (Sequence[Change]) – Candidate changes (see mergeset.sources).

  • base (Optional[str]) – What to merge onto. Default: the merge base of every change’s own base, which is the only choice that is fair to all of them.

  • validate (Optional[Callable[[str], ValidationOutcome]]) – worktree -> ValidationOutcome; default is a fail-fast pytest run. Pass merge_only_validation() for a free first pass.

  • resolver (Optional[Callable[[str, Sequence[str]], Tuple[bool, str]]]) – Optional AI-assisted conflict resolver (results are flagged).

  • artifacts (Optional[Mapping[str, MutableMapping]]) – The artifact stores, as a {kind: MutableMapping} mall (see mergeset.storage.artifact_mall()). This is the storage seam: pass a mall over S3 and the evaluation log goes to S3 with no other change. Default: local files under ~/.local/share/mergeset/.

  • log_path (Optional[str]) – The evaluation log — the single source of truth. Defaults to <artifact root>/evaluations/<repo-slug>.jsonl (see mergeset.storage), outside the analysed repository. Reusing an existing one makes a re-run nearly free. Only rows evaluated against the same base and heads are reused (see ADR 0028).

  • trust_unpinned (Optional[bool]) – Reuse log rows written before rows recorded their commits (an old log). Default: the log’s own setting, which is off. Only when the heads have not moved since those rows were written.

  • weight (Optional[Callable[[Change], float]]) – Change -> cost of dropping it; default is size-based.

  • pairwise_preoracle (bool) – Use git merge-tree to find textual conflicts for free before spending any evaluation.

  • decompose (bool) – Use file-overlap components to find conflicts cheaply. The components are always searched first, because a conflict found inside a small component is a conflict found for a fraction of the price; whether their answers are then trusted to combine is component_local.

  • component_local (Optional[bool]) – Assert that the validator cannot see across components — i.e. that two changes touching disjoint files can never fail together. True for a merge-only or per-file validator; **false for any whole-repo test run**, which can fail on generated artifacts, barrel exports, snapshots, type checks or project-wide lint that no changed-file overlap predicts. When false (the default), the combined result is verified by a global search seeded with every conflict the components found. None (the default) asks the validator: one may set validate.component_local = True to declare it, as merge_only_validation() does.

  • check_base (bool) – Evaluate the base commit on its own before anything else, so a broken base or a misconfigured validator is a refusal rather than 15 confident failures.

  • use_ci_status (bool) – Treat a change whose own CI is red as a size-1 conflict.

  • max_evaluations (Optional[int]) – Budgets; partial results are always returned.

  • max_seconds (Optional[float]) – Budgets; partial results are always returned.

  • max_sets (Optional[int]) – Budgets; partial results are always returned.

  • reuse_worktree (Optional[str]) – Reuse one worktree for every evaluation instead of a fresh one, so an expensive setup step (npm install, a build cache) is paid once rather than per evaluation. Pair it with mergeset.validation.staged_validation().

  • on_event (Optional[Callable[[str, dict], None]]) – (event, payload) progress callback.

Return type:

Analysis

Returns:

An Analysis.
