mergeset.base#

Core data structures and vocabulary of mergeset.

The unit of work is a change: a commit range base..head. Branches, pull requests and explicit commit lists are merely sources that produce changes (see mergeset.sources). Everything downstream — the evaluation log, the solver, the report — speaks only of changes, identified by their string id.

A change set is a frozenset of change ids. Sets are the atoms the solver reasons about; they are serialized as sorted lists so the JSONL log is stable and diffable.

class mergeset.base.Change(id, head, base, source='branch', weight=None, meta=<factory>)[source]#

Bases: object

One candidate change: everything between base and head.

Parameters:

  • id (str) – Short stable identifier, used everywhere else (log, report, CLI).

  • head (str) – Commit-ish holding the change (branch name, sha, PR head).

  • base (str) – Commit-ish the change is measured against.

  • source (str) – Which source produced it ('branch', 'pr', 'commit').

  • weight (Optional[float]) – Cost of dropping this change. The solver drops the cheapest changes it can when it must drop something, so a high weight means “keep me”. None means “let the weighting policy decide”.

  • meta (Mapping[str, Any]) – Source-specific extras (PR number, author, CI status, draft flag…).

>>> c = Change(id='fix-a', head='origin/fix-a', base='origin/main')
>>> c.id, c.source
('fix-a', 'branch')

class mergeset.base.Evaluation(subset, verdict, stage=None, merge=None, validation=None, duration=0.0, at=None, note='', base_sha=None, heads=<factory>, validator=None, resolver=None, cached=False)[source]#

Bases: object

One row of the evaluation log — the single source of truth.

Everything else (conflict set, known-good/known-bad closure, merge plan, reports) is derived from a sequence of these and is re-derivable.

A row is about the commits that were actually merged, not about the ids: base_sha and heads (change id -> head sha) pin it to them, so a row written before a branch was rewritten is never mistaken for an answer about the rewritten branch (i2mint/mergeset#23). Rows written before pinning existed carry neither and read back as unpinned; see mergeset.log.EvaluationLog. validator pins it to what was run on that tree, the same way (i2mint/mergeset#32): the same commits under a different test command are a different question.

base_sha: str | None = None#

Full sha of the base the set was merged onto. None on unpinned rows.

cached: bool = False#

True when this came from the log rather than from a real run. Not serialized: it is a fact about this lookup, not about the evaluation.

property merge_dependent: bool#

True iff how conflicts were resolved decided this row’s outcome.

An assisted merge exists only because a resolver resolved it; a textual conflict stands only because none did. A clean merge is the same tree whatever the resolver, so its verdict answers any of them.

>>> Evaluation(frozenset('a'), Verdict.PASS).merge_dependent
False
>>> Evaluation(frozenset('a'), Verdict.PASS,
...            merge=MergeOutcome(True, assisted=True)).merge_dependent
True
>>> Evaluation(frozenset('ab'), Verdict.FAIL,
...            merge=MergeOutcome(False, 'conflict')).merge_dependent
True

class mergeset.base.MergeOutcome(ok, reason='conflict', conflicting_files=(), assisted=False, assist_diff=None, order=(), detail='', resolved_commit=None)[source]#

Bases: object

Result of merging a change set onto its base.

reason is load-bearing. “These changes conflict with each other” and “we could not run the experiment” are completely different facts, and conflating them is how a run reports 0 of 15 mergeable, complete with total confidence when the real problem was a bad worktree path. Only reason == 'conflict' may ever enter the conflict set; an 'error' aborts, because a set that was never tested has told us nothing.

reason: str = 'conflict'#

'conflict' (a real textual conflict) or 'error' (the merge could not be attempted: bad path, missing ref, unusable worktree).

resolved_commit: str | None = None#

base plus every head, conflicts resolved. A deeper tier checks this commit out instead of asking the resolver again (i2mint/mergeset#30). Not in to_jdict(): Evaluation.to_jdict() stores it beside merge, because releases before #30 build MergeOutcome(**merge) and would refuse the log.

Type:

The merge commit an assisted resolution produced

class mergeset.base.StageRun(name, duration=0.0, returncode=None, skipped=False)[source]#

Bases: object

What one stage of a staged validation did, and what it cost.

A stage skipped because its fingerprint matched (an install whose lockfile did not change) is recorded too, with skipped=True and no time: that skip is often the largest term in what an evaluation costs, and a log that cannot show it cannot confirm it (i2mint/mergeset#17).

>>> StageRun.from_jdict(StageRun('setup', 33.0, 0).to_jdict())
StageRun(name='setup', duration=33.0, returncode=0, skipped=False)
