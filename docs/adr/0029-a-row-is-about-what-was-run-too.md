# 0029 — A log row is about what was run too, not only about the commits

ADR 0028 pinned rows to commits and left the validator out of the key: "a changed validation command under one log is still the user's to notice." Tiers made that common rather than rare. A tier's log is keyed by repository and tier name, and a tier is the thing people tune, so `--tier u:true` followed by `--tier u:false` reused the first run's passes as answers to the second (i2mint/mergeset#32). The untiered log did the same when `--validate-command` changed.

**Decision.** A validator may say what it runs: a `validator_fingerprint` attribute, read by `mergeset.validation.fingerprint_of`. Every shipped validator sets one, `kind:` followed by a digest of what the validator runs: the command or pytest arguments, the stages (name, command, timeout, required), the timeout, the environment, and the retries of `flake_tolerant` (`env=None` and `env={}`, `60` and `60.0`, digest alike). A stage's own `fingerprint` (which skips a setup that already ran in a worktree) is left out, since it does not change the verdict. Every `Evaluation` row records the fingerprint of the validator that judged it (`recorded_fingerprint`), and `EvaluationLog.pinned(validator=)` scopes a log to one: `analyze` pins to its validator, `analyze_tiered` pins each tier's log to that tier's validator. How a set was *merged* is not part of the key: a PASS reached through an assisted resolution is reused by a run without the resolver (i2mint/mergeset#30 is about the resolver across tiers).

**Rows judged by another validator are kept,** like rows about other commits: they are listed by `stale` (and by `other_validator`), not counted, and the analysis note says how many were judged by a different validator. `show-log` warns when rows mix validators, counting rows that record none as one more. Their timings do not price the tier either: an edited command is a new price, and a 2 s check's timings must not admit a 600 s one into a budget. Rows recording no validator still price it: they are most often from the same command, and leaving them out would price every tier from its default on the first run after upgrading, the over-admission ADR 0026's measured cost exists to prevent. If the command was edited before the upgrade, that first run is priced from the old command's timings.

**Old rows.** Rows written before this record no validator. They load, are listed by `unpinned`, and are not trusted by default: they may have been judged by a command that has since changed. `trust_unpinned` / `--trust-unpinned-log` adopts them, as it adopts rows from before ADR 0028. A row that *records* a different validator is never adopted.

**A validator that cannot say what it runs** (a user callable, or `pytest_validation` with a `select_paths` callable) has no fingerprint. Its rows record `unknown`, not nothing: they match only other `unknown` rows (so two user callables share a log as before), never a fingerprinted validator's rows in either direction, and `trust_unpinned` does not mistake them for rows from before this record. A log pinned with no validator at all (`EvaluationLog.pin` called without one, in library use) stamps `unknown` too, for the same reason. A callable's name says nothing about what it selects or checks, so no fingerprint is guessed from it. Its author can set `validate.validator_fingerprint = 'smoke-v2'` and bump it when the check changes; `callable_validation` keeps it. A `functools.wraps` wrapper copies the wrapped validator's fingerprint, so a wrapper that changes what is checked must set its own.

**Why per row, not per file.** Putting the fingerprint in the log's file name would also stop the reuse, but it would leave old files orphaned rather than reported, and lose the timings of rows about older commits, which still price the tier (ADR 0026). Per-row pinning keeps one log per tier and reuses the machinery of ADR 0028.

**Cost on upgrade.** Rows written before this record no validator, including rows already pinned to commits, so each log is evaluated in full once after upgrading unless `--trust-unpinned-log` is passed.
